# SM-305: Silk history queries leak their message in the group 3 divisions

- Original: `COneByOneProcessor::StartSilkQuery_631A` (0x41d280), SR_ShardManager
- Rewrite: `COneByOneProcessor::StartSilkQuery_631A` in `SilkroadOnline/Server/ShardManager/OneByOneProcessor.cpp`
- Severity: minor

## What the original does

The 0x631A request is built first. When `SelfDivision_IsInGroup3` returns 1 the function
returns without relaying the request, without releasing it and without an answer.

## Effect

In those divisions every silk history job leaks one message and stays busy until the 60 s
timeout completes it. The rewrite does the same.

## Fix

Check the division before allocating the message, and answer 0xB91F at once.
