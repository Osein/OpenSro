# SM-302: A failed revive statement is reported as a restored character

- Original: `CShardMaintainer::OnReviveChar` (0x431c30), SR_ShardManager
- Rewrite: `CShardMaintainer::OnReviveChar` in `SilkroadOnline/Server/ShardManager/ShardMaintainer.cpp`
- Severity: minor

## What the original does

The answer code starts at 0x401 (restored) and is changed to 0x402 only when `_ReviveChar`
ran and returned 0 or less. When the statement itself fails (no connection, SQL error), the
code stays 0x401 and the main process gets {3, JID, CharID, BYTE 1}.

## Effect

The main process treats the character as restored although the database still has it
deleted; it was also taken out of the delete buckets, so it is never deleted permanently until
the next start. The rewrite does the same.

## Fix

Set 0x402 when `ExecDirectWithReturnValue` fails.
