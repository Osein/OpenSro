# SM-140: The record is used after it went back to its table

- Original: `CServerEvent::ResetAndDetach` (0x678c10), `CServerEventReward::ResetAndDetach` (0x6817c0), SR_ShardManager
- Rewrite: `CServerEvent::ResetAndDetach`, `CServerEventReward::ResetAndDetach` in `SilkroadOnline/Server/ShardManager/ServerEvent.cpp`
- Severity: minor

## What the original does

Both functions hand the record to CDBTable::FreeRecord (CDBObject_DetachFromOwner) and then
call its vftable slot 5 (InitData). Without shard DB they call InitData without checking the
record.

## Effect

With an allocator that deletes the record this is a use after free; with a pooling allocator
the free record is reset again. The rewrite makes the same calls.

## Fix

Reset the record before it is freed, and check it.
