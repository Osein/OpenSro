# SM-142: DeleteServerEvent loses the event on its late failures

- Original: `CServerEventMgr::DeleteServerEvent` (0x67f5c0), SR_ShardManager
- Rewrite: `CServerEventMgr::DeleteServerEvent` in `SilkroadOnline/Server/ShardManager/ServerEventMgr.cpp`
- Severity: minor (leak)

## What the original does

The event is erased from the event map first. When it has no reference or no message can be
allocated, the function returns FALSE without the final update and without releasing the event
to its pool; without reference the detecting target entry stays as well.

## Effect

The event object and its record leak and the last progress is not written. The rewrite returns
the same way.

## Fix

Check the reference and allocate the message before erasing, or release the event on these
paths.
