# SM-113: The log functions keep the job on their early failures

- Original: `ServerEventLog_LogDetecting` (0x47b600), `ServerEventLog_LogCompletion`
  (0x47b7f0), `ServerEventLog_LogReward` (0x47b980), SR_ShardManager
- Rewrite: the same functions in `SilkroadOnline/Server/ShardManager/ShardLogJobs.cpp`
- Severity: minor

## What the original does

The AQ_ServerEventLog job is taken from its pool first. When the event has no reference, the
user of the reward is not found or the text does not fit, the function asserts and returns
FALSE without giving the job back (only a failed DB_Insert_LogServerEvent returns it).

## Effect

Each such failure loses one pooled job (and its overlap job ID).

## Fix

Return the job to its pool (vftable slot 3) on every failure path.
