# SM-315: Log job descriptions grow with every reuse of the job object

- Original: `AQ_ServerEventLog::BuildDescription` (0x47c040) with `AQ_ServerEventLog::vf02`
  (0x47a810), `AQ_SiegeLogSelector::BuildDescription` (0x47f8d0), SR_ShardManager
- Rewrite: `AQ_ServerEventLog::BuildDescription` in
  `SilkroadOnline/Server/ShardManager/AQServerEvent.cpp`, `AQ_SiegeLogSelector::BuildDescription`
  in `SilkroadOnline/Server/ShardManager/AQSiegeJobs.cpp`
- Severity: minor

## What the original does

The description of the console answer is built by appending " [ServerEvent] (<type>)" or
" [SiegeFortress] (<type>)" to the description member. Nothing assigns the member first, and
the reset of the pooled job (vftable slot 2) does not clear it.

## Effect

The first request answered by a job object gets the expected text; every later request that
reuses the same pooled object gets the descriptions of all earlier requests in front of its
own. The rewrite does the same.

## Fix

Assign the first part instead of appending it, or clear the description in the reset.
