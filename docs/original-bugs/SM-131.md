# SM-131: A service-start event without a group crashes before the NULL check

- Original: `CShard_ScheduleManager::OnServiceStartSchedule` (0x663690), SR_ShardManager
- Rewrite: `CShard_ScheduleManager::OnServiceStartSchedule` in `SilkroadOnline/Server/ShardManager/ShardSchedule.cpp`
- Severity: minor (the library never queues an event without a group)

## What the original does

It calls `CScheduleGroup::FindActiveSchedule` on the event's group first and only then checks
the group for NULL ("Do not Found ScheduleDefine").

## Effect

An event without a group faults inside the map lookup instead of logging. The rewrite makes the
same call in the same order.

## Fix

Check the group before looking up the schedule.
