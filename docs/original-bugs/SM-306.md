# SM-306: A repeated silk history key leaks its request data

- Original: `COneByOneProcessor::OnCashRequest` (0x41ce10) / `RegisterJob` (0x41d050), SR_ShardManager
- Rewrite: `COneByOneProcessor::RegisterJob` in `SilkroadOnline/Server/ShardManager/OneByOneProcessor.cpp`
- Severity: minor

## What the original does

`OnCashRequest` takes a `sSilkHistoryData` from its pool before `RegisterJob` checks the key.
When a job with the key exists, `RegisterJob` returns without storing or freeing it.

## Effect

Each repeated request keeps one pool object for good. The rewrite does the same.

## Fix

Return the data to its pool when the key is already registered.
