# SM-313: The log query jobs leak the selected records

- Original: `AQ_LogSelector::vf06` (0x470130), `AQ_ScheduleLog::vf06` (0x473060) and the other
  log selectors of the SMC console, SR_ShardManager
- Rewrite: `AQ_LogSelector::Execute` in `SilkroadOnline/Server/ShardManager/AQLogSelector.cpp`,
  `AQ_ScheduleLog::Execute` in `SilkroadOnline/Server/ShardManager/AQScheduleJobs.cpp` and the
  other jobs marked with this ID
- Severity: minor

## What the original does

The log rows are selected into a record list with `CDBTable::ExecSelectWithCustomTail`, written
into the console answer, and the list is then destroyed as a plain `std::list`. The record
objects are never handed back to their table.

## Effect

Every log query of the console leaks one record object per selected row (up to 50 per query,
or the whole history of an item serial). The rewrite does the same.

## Fix

Free the list through its table (`CDBObjectList_DetachAndClear`) after writing the answer and
when the select fails.
