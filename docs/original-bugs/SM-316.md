# SM-316: The siege data answer counts requests it does not write

- Original: `AQ_SiegeDataSelector::WriteFortressData` (0x47dfd0), SR_ShardManager
- Rewrite: `AQ_SiegeDataSelector::WriteFortressData` in
  `SilkroadOnline/Server/ShardManager/AQSiegeJobs.cpp`
- Severity: minor

## What the original does

The siege requests of the fortress are written as a DWORD count (the size of the selected
`_SiegeFortressRequest` list) followed by {BYTE request type, guild name} per request. A
request whose guild ID is 0 or whose guild is not in the guild manager is skipped without
writing anything, but the count already includes it.

## Effect

The console reads more request entries than the answer holds and misinterprets the end of
the message (or fails to parse it). The rewrite does the same.

## Fix

Count only the requests that are written, or write an empty name for the missing guilds.
