# SM-352: The pet query leaks records when an item query fails

- Original: `AQ_CharDataSelector::QueryPetDetail` (0x46c180), SR_ShardManager
- Rewrite: `AQ_CharDataSelector::QueryPetDetail` in
  `SilkroadOnline/Server/ShardManager/AQCharDataQueries.cpp`
- Severity: minor

## What the original does

Target 9 first selects the latest `_CharCOS` row of the character, then the `_Items` rows of
its inventory and of the storage of its account. When the inventory query (or its format)
fails, only the inventory list is freed; the `_CharCOS` records are destroyed as a plain
`std::list`. When the storage query fails, the `_CharCOS` records and the inventory items are
both left behind the same way.

## Effect

A failing item query of the pet page leaks the selected record objects. The rewrite does the
same.

## Fix

Free the pet list through the `_CharCOS` table and the item lists through the `_Items` table on
every failure path, like the `LoadPetItem` failure path does.
