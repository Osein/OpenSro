# SM-318: A cut SMC log statement of the character data editor is still executed

- Original: `BuildSMCLog` (0x48bb10) and `CCharDataEditor::vf03` (0x48bc80), SR_ShardManager
- Rewrite: `BuildSMCLog` and `CCharDataEditor::Execute` in
  `SilkroadOnline/Server/ShardManager/CharDataEditor.cpp`
- Severity: minor

## What the original does

After a successful edit, `BuildSMCLog` formats the `{CALL _ADDLOGCHAR (...)}` or
`{CALL _ADDLOGITEM (...)}` statement into a 0x80-byte buffer, with the edit arguments of the
request (`m_strEditDesc`, up to 0x7F characters) as the last text. When the text does not fit,
`StringCchPrintfA` cuts it and `BuildSMCLog` only logs "failed to make string!". The caller
copies the buffer into `m_strLogQuery` and executes it on the log database whenever it is not
empty.

## Effect

An edit with long arguments (names, item fields) runs a cut statement: the closing quote and
brace are missing, so the log call fails on the database and the SMC log row of the edit is
lost. The rewrite does the same.

## Fix

Keep the default "no log" text (or clear the buffer) when the formatting fails, or use a buffer
large enough for the longest arguments.
